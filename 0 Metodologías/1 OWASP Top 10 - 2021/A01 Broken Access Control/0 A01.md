# A01:2021 - Broken Access Control 

Tags: #OWASP 

```bash 
Es posible que las limitaciones impuestas a los usuarios autenticados no se implementen adecuadamente. Esto puede ser explotado por atacantes para obtener acceso no autorizado a funciones, información, cuentas, archivos confidenciales o incluso modificar permisos. 
```

```bash 
Ocurre cuando un usuario puede acceder a datos o funcionalidades que no debería

- Causa: 
	1. Falta de verificación en el servidor sobre qué usuario es el dueño de la información solicitada

- Mitigación: 
	1. Validar siempre la autorización en el servidor para cada recurso
	2. Implementar controles de acceso basados en roles RBAC '(Role-Based Access Control)'
```


## A02:2021 - Cryptographic Failures 

```bash  

- Causas:
	1. 

- Mitigación: 
	1. 'En tránsito:' Forzar HTTPS con TLS 1.2 o 1.3
	2. 'En reposo:' Cifrar datos sensibles con AES-256
	3. Passwords: Usar hashing con bcrypt, Argon2 o scrypt + salt.
	4. Tokens y archivos: Firmar digitalmente con HMAC o claves privadas.
	5. No exponer datos sensibles en logs, URL o mensajes de error
```

| **Vulnerabilidad**                | **Descripción** | **Ejemplo de Prueba / Payload** |
|-----------------------------------|-----------------|---------------------------------|
| **Datos en tránsito sin cifrar**  | La aplicación usa HTTP en lugar de HTTPS, exponiendo datos sensibles. | Interceptar credenciales con un proxy en `http://example.com/login`. |
| **TLS débil o mal configurado**   | Uso de protocolos o cifrados obsoletos (TLS 1.0, SSLv3) o suites débiles. | `nmap --script ssl-enum-ciphers -p 443 target.com`. |
| **Exposición de datos sensibles en respuestas** | Datos como contraseñas, tarjetas o tokens se exponen en texto claro en respuestas HTTP. | Revisar respuesta de `/api/user` devolviendo `password: 12345`. |
| **Passwords sin hashing seguro**  | Contraseñas guardadas en texto plano o con hashing inseguro (MD5, SHA1). | Dump de DB con `SELECT password FROM users;` revelando contraseñas en texto plano. |
| **Uso de cifrados inseguros**     | Uso de algoritmos rotos o inseguros (DES, RC4, MD5). | Ver código con `hash = MD5(password)`. |
| **Falta de protección de datos en reposo** | Datos sensibles (ej. tarjetas) guardados sin cifrar en base de datos o archivos. | Acceder a `/var/www/db/cards.txt` con datos en claro. |
| **Exposición en URL o logs**      | Datos sensibles se pasan por URL o quedan en logs. | `https://site.com/login?user=omar&pass=123456`. |
| **Falta de integridad de datos**  | Archivos o tokens no tienen firmas, permitiendo su manipulación. | Subir archivo manipulado porque no se verifica el checksum o firma. |

## A03:2021 - Injection 

```bash  


- Causas:
	1. Confiar en los datos del usuario sin validación ni sanitización
	2. Concatenar strings para generar consultas SQL, LDAP o comandos
	3. Falta de uso de 'prepared statements' (consultas parametrizadas)
	4. Inyección en plantillas o cabeceras HTTP sin escapes adecuados

- Mitigación: 
	1. 'Validar y sanitizar' todas las entradas (listas blancas, no listas negras).
	2. Usar 'consultas parametrizadas' para SQL, NoSQL y LDAP.
	3. Escapar caracteres especiales en plantillas ('{{ }}') y cabeceras
	4. Principio de 'menor privilegio' en las cuentas de base de datos
	5. Usar WAF y herramientas de análisis como SQLMap o Burp para detectar problemas.
```

| **Vulnerabilidad**            | **Descripción** | **Ejemplo de Prueba / Payload** |
|-------------------------------|-----------------|---------------------------------|
| **SQL Injection (SQLi)**      | Entrada no validada se inyecta en una consulta SQL, permitiendo manipular la base de datos. | `' OR '1'='1` en campo de login para saltar autenticación. |
| **NoSQL Injection**           | Datos mal validados se inyectan en consultas NoSQL como MongoDB. | `{ "$ne": null }` en campo de búsqueda para obtener todos los registros. |
| **Command Injection**         | Entrada del usuario ejecuta comandos en el sistema operativo. | `; cat /etc/passwd` en un campo de formulario que llama a un script de shell. |
| **LDAP Injection**            | Entrada se inserta en consultas LDAP para modificar resultados. | `*)(|(user=*))` en campo de búsqueda LDAP para listar usuarios. |
| **XPATH Injection**           | Entrada manipulada afecta consultas XPath a XML. | `' or '1'='1` en una consulta XPath para saltar validaciones. |
| **Template Injection**        | Inyección en motores de plantillas (Jinja2, Twig) permitiendo ejecución de código. | `{{7*7}}` devuelve `49` en Jinja2 vulnerable. |
| **Header Injection**          | Modificación de cabeceras HTTP para ejecutar acciones no previstas. | `\r\nSet-Cookie: admin=true` en cabeceras manipuladas. |
| **Email/SMTP Injection**      | Manipulación de campos en formularios de contacto para enviar correos arbitrarios. | `test@test.com\nBCC: attacker@mail.com` en campo “To”. |

## A04:2021 - Insecure Design

```bash  

- Causas: 
	1. 

- Mitigación: 
	1. Realizar 'Modelado de amenazas' (Threat Modeling) en fases tempranas
	2. Implementar validaciones robustas en el backend 
	3. Diseñar flujos seguros y con controles claros.
	4. Incorporar autenticación multifactor y cifrado cuando aplique.
	5. Aplicar el principio de menor privilegio.
	6. Gestionar sesiones con políticas de expiración y renovación.
	7. Proteger contra ataques comunes (CSRF tokens, rate limiting, WAF).
```

| **Vulnerabilidad**                | **Descripción**                                             | **Ejemplo de Prueba / Payload**                             |
|----------------------------------|-------------------------------------------------------------|-------------------------------------------------------------|
| **Falta de Modelado de Amenazas**| No considerar riesgos y vectores de ataque durante el diseño| Revisar si la app permite múltiples intentos de login sin límite o bloqueo. |
| **Ausencia de validación de entrada** | Falta de controles para entradas maliciosas en puntos críticos | Enviar datos maliciosos en formularios sin validación (scripts, payloads XSS, SQLi). |
| **Flujos inseguros**             | Procesos que permiten acciones no autorizadas o inconsistentes | Cambiar parámetros para saltar pasos de validación o pagos. |
| **Ausencia de mecanismos de seguridad** | Falta de características como autenticación multifactor o cifrado | Verificar que la app no requiere MFA en accesos críticos. |
| **Diseño sin principio de menor privilegio** | Usuarios tienen más permisos de los necesarios para sus funciones | Un usuario normal puede acceder a funciones de administrador. |
| **No implementación de controles de sesión seguros** | Falta de manejo adecuado de sesiones, como expiración o invalidación | Comprobar si las sesiones permanecen activas tras cerrar sesión. |
| **Falta de protección contra ataques comunes** | No proteger contra CSRF, fuerza bruta, o robo de sesiones | Intentar ataques de fuerza bruta o CSRF en formularios sin protección. |

## A05:2021 - Security Misconfiguration 

```bash  


- Causas: 
	1. 

- Mitigación: 
	1. Deshabilitar modo debug en producción
	2. Cambiar credenciales por defecto y fortalecer contraseñas.
	3. Restringir acceso a archivos y directorios sensibles.
	4. Configurar correctamente headers de seguridad HTTP.
	5. Desactivar servicios no usados y proteger los necesarios.
	6. Personalizar y limitar mensajes de error.
	7. Establecer permisos mínimos necesarios para archivos y carpetas.
```

| **Vulnerabilidad**                | **Descripción**                                             | **Ejemplo de Prueba / Payload**                             |
|----------------------------------|-------------------------------------------------------------|-------------------------------------------------------------|
| **Modo debug activo en producción** | Aplicación muestra información sensible por errores o logs | Página de error que muestra stack trace o variables internas. |
| **Configuración por defecto insegura** | Uso de credenciales por defecto o configuraciones sin cambios | Usuario y contraseña admin/admin en panel de control. |
| **Exposición de directorios o archivos sensibles** | Acceso a archivos de configuración o backups desde la web | Acceso a `/backup.zip`, `/config.php`, `.env` sin restricciones. |
| **Headers de seguridad ausentes o incorrectos** | Falta de CSP, X-Frame-Options, HSTS u otros headers | Página vulnerable a clickjacking o XSS por falta de CSP. |
| **Servicios innecesarios expuestos** | Servicios como administración, FTP, o bases de datos accesibles públicamente | Puerto SSH o base de datos expuesta sin firewall. |
| **Errores detallados visibles para usuarios** | Mensajes de error que revelan rutas, tecnologías o queries | Error SQL mostrando consulta completa en respuesta. |
| **Permisos incorrectos en archivos o directorios** | Archivos con permisos que permiten lectura o escritura no autorizada | `/var/www/html` con permisos 777. |

## A06:2021 - Vulnerable and Outdated Components

```bash  


- Causas: 
	1. 

- Mitigación: 
	1. Mantener siempre actualizadas las dependencias y frameworks.
	2. Utilizar herramientas de análisis de seguridad para dependencias (Dependabot, OWASP Dependency-Check).
	3. Eliminar componentes o código innecesario.
	4. Usar subresource integrity (SRI) para recursos externos.
	5. Monitorizar bases de datos públicas de vulnerabilidades.
```

| **Vulnerabilidad**                | **Descripción**                                             | **Ejemplo de Prueba / Payload**                             |
|----------------------------------|-------------------------------------------------------------|-------------------------------------------------------------|
| **Uso de librerías o frameworks obsoletos** | Componentes con vulnerabilidades conocidas no actualizadas | Ver versión antigua de jQuery vulnerable a XSS (`jquery-1.8.js`). |
| **Dependencias con vulnerabilidades** | Bibliotecas usadas tienen fallos de seguridad conocidos | Resultado de `npm audit` muestra paquetes inseguros. |
| **Falta de parches de seguridad** | No aplicar actualizaciones que corrigen vulnerabilidades | Servidor web sin parche para CVE conocido. |
| **Componentes no utilizados activos** | Código o librerías que ya no se usan pero siguen presentes | Scripts antiguos en la web que no se usan pero son accesibles. |
| **Carga de recursos inseguros** | Uso de recursos externos sin verificar seguridad o integridad | Cargar JS desde CDN sin validar hash (Subresource Integrity). |
| **Falta de gestión de dependencias** | No auditar ni controlar las dependencias del proyecto | No usar herramientas de escaneo de vulnerabilidades. |
